# MealMate frontend

The web app that people install on their iPhone Home Screen. It is a static React build that the
backend serves next to `/api`; in development it runs on the Vite dev server and proxies `/api` to
the backend. What to build is in [`docs/requirements.md`](../docs/requirements.md), how and when in
[`docs/plan.md`](../docs/plan.md) (§ 8 covers the frontend).

## Stack

| Area         | Choice                                                                                 |
| ------------ | -------------------------------------------------------------------------------------- |
| Framework    | React 19, TypeScript (strict), Vite                                                    |
| Routing      | React Router (`react-router`)                                                          |
| Styling      | Tailwind CSS v4 with design tokens, shadcn/ui components (source copied), lucide icons |
| Server state | TanStack Query                                                                         |
| API client   | `openapi-fetch` with types generated by `openapi-typescript`                           |
| i18n         | i18next + react-i18next, `Intl` for number and date formats                            |
| PWA          | `vite-plugin-pwa` (injectManifest) with a Workbox service worker                       |
| Tests        | Vitest, Testing Library, jsdom                                                         |
| Quality      | ESLint (typescript-eslint, react-hooks, jsx-a11y), Prettier, `tsc`                     |

Node.js ≥ 22.12 (CI and the image use Node 24).

## Commands

Run these in `frontend/` (the repository root has `make` targets for the whole stack).

| Command                 | What it does                                                            |
| ----------------------- | ----------------------------------------------------------------------- |
| `npm ci`                | Install the locked dependencies                                         |
| `npm run dev`           | Dev server on http://localhost:5173 with hot reload                     |
| `npm run build`         | Type-check and build into `dist/` (served by the backend in production) |
| `npm run preview`       | Serve the production build locally                                      |
| `npm run test`          | Unit and component tests (Vitest)                                       |
| `npm run lint`          | ESLint                                                                  |
| `npm run format`        | Check formatting (Prettier); `npm run format:write` fixes it            |
| `npm run typecheck`     | TypeScript check of the app, the service worker and the Vite config     |
| `npm run openapi:types` | Regenerate `src/api/generated/schema.ts` from `openapi.json`            |

The dev server proxies `/api` to `VITE_API_PROXY_TARGET` (default `http://localhost:8080`), so a
backend must be running. From the repository root, `make dev` starts backend and frontend with hot
reload, `make openapi` regenerates the API description and types, and `make e2e` runs the
end-to-end suite against the production image.

## Folder structure

```
frontend/
├── index.html              # no inline scripts or styles (CSP)
├── public/                 # favicon.svg, apple-touch-icon.png, icons/ (PWA icons)
├── assets/icon.svg         # source artwork of the PNG icons
├── scripts/                # generate-icons.mjs (re-renders the PNG icons)
└── src/
    ├── main.tsx            # entry: i18n, styles, service-worker registration, <App />
    ├── api/                # client.ts (openapi-fetch, timeouts), errors.ts (ApiError)
    │   └── generated/      # openapi.json + schema.ts, generated, never edited by hand
    ├── app/                # App, router, providers, Layout (bottom tab bar), UpdatePrompt
    ├── features/<feature>/ # screens and hooks of one feature; server calls in `api.ts`
    ├── components/ui/      # shadcn/ui building blocks
    ├── components/         # shared app components (Screen, EmptyState, ExternalLink)
    ├── i18n/               # de.json, en.json, index.ts (setup, language switch), format.ts
    ├── lib/                # small helpers (`cn`)
    ├── styles/             # tokens.css (design tokens), index.css (Tailwind entry)
    ├── sw/sw.ts            # service worker
    ├── test/               # test setup and render helpers
    └── testIds.ts          # every data-testid
```

## Conventions

These keep the frontend restylable and the tests stable (MNT-04). Reviews check them.

- **All user-facing text goes through i18n keys** in `src/i18n/*.json`. No hard-coded strings in
  components, including `aria-label`s. Keys are flat: `feature.screen.element`; errors are
  `error.<code>`, field errors `error.field.<code>`, reminders `reminder.<n>`. Keys are
  type-checked: `t('typo')` fails `tsc`.
- **API calls only through `src/api`.** Features call the shared `api` client (typed from
  OpenAPI) in their `features/<feature>/api.ts` and expose TanStack Query hooks. Wrap calls in
  `unwrap()`, which rejects with an `ApiError` (`status`, `code`, `params`, `fields`). Show errors
  with `errorMessage(t, error)` from `src/i18n/errors.ts`, never with backend text.
- **Timeouts:** reads time out after 8 s, writes after 15 s (`client.timeout`); an unreachable
  server gives `client.network`. Override per request with `...withTimeout(ms)`.
- **No domain calculations in the frontend** (MNT-02). Amounts, conversions, aggregation,
  rounding, nutrition and permissions come from the backend; the frontend formats and displays
  (`src/i18n/format.ts`: `formatNumber`, `formatDate`, `parseAmount`).
- **Test IDs only from `src/testIds.ts`.** E2E tests select by role, accessible name or test ID,
  never by CSS class or DOM structure (QA-05). Every interactive element needs an accessible name.
- **UI building blocks live in `src/components/ui/`** (shadcn/ui source, adapted: every size keeps
  a 44 × 44 pt tap target via `min-h-(--tap-target)`, form controls use
  `text-(length:--control-font-size)`, and focus rings use the full `ring` colour). The shadcn
  registry can add more (`npx shadcn@latest add <name>`, configured by `components.json`); review
  the generated code against these conventions.
- **Design tokens in `src/styles/tokens.css`.** Components use token classes (`bg-primary`,
  `text-muted-foreground`, …), never raw colours. Dark mode follows the device setting only (no JS
  theme switch). Sizes are in `rem`, so text follows the iPhone text-size setting; the
  `--tap-target` and `--control-font-size` tokens keep a px floor under touch targets and form
  text. Colour is never the only signal (e.g. the active tab has a filled pill).
  `prefers-reduced-motion` turns animations off.
- **Content Security Policy:** the backend sends a strict CSP. No inline `<script>` or `style=""`
  in `index.html`, no `eval`, no third-party requests of any kind (fonts, CDNs, analytics); every
  asset is bundled and served by the app (SEC-08). `dangerouslySetInnerHTML` is banned by ESLint
  (SEC-13). External links open with `rel="noopener noreferrer"` (`ExternalLink`).
- **Service worker:** precaches the built app shell and serves navigations from it; it never
  caches or answers `/api` (`src/sw/navigation.ts`). The app also checks for a new version when it
  returns to the foreground; a new version waits until the user taps "Reload" in the update prompt.
- **Queries always send their request** (`networkMode: 'always'` in `src/app/queryClient.ts`), also
  when the browser reports being offline, so a screen shows "can't reach MealMate" instead of
  waiting.

## API types

`src/api/generated/openapi.json` is exported from the backend and `schema.ts` is generated from
it. Both are committed, and CI fails if they are out of date. After changing the API, run from the
repository root:

```bash
make openapi
```

This runs `mealmate export-openapi` in the backend and then `npm run openapi:types`. Never edit
the generated files by hand.

## Translations

**Adding a string:** add the key to **both** `src/i18n/de.json` and `src/i18n/en.json`. The
translation test fails if a key is missing in one file, if a translation is empty, if the
`{{placeholders}}` or `<tags>` differ between languages, or if an error code from `openapi.json`
has no `error.<code>` translation. German texts are written as a German would say them, not
translated word for word.

**Adding a language** (I18N-01):

1. copy `src/i18n/en.json` to `src/i18n/<lang>.json` and translate every value;
2. register it in `src/i18n/index.ts`: add the code to `LANGUAGES`, its own name to
   `LANGUAGE_NAMES` and the file to `resources`;
3. add its `Intl` locale to `LOCALES` in `src/i18n/format.ts`;
4. add the language to the backend's `language` enum (users store their choice, from M2 on).

## Icons

The PNG icons are rendered from `assets/icon.svg` and committed. After changing the artwork:
`npm install --no-save sharp && node scripts/generate-icons.mjs`. The favicon is
`public/favicon.svg`. The basket glyph is Lucide's `shopping-basket` (ISC licence).
